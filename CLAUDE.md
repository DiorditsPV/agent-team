# agent-team — бриф для агентов

Инструмент `team`: поднимает набор агентов Claude Code по описанным ролям для любого проекта. Спецификация — `docs/SPEC.md`; при расхождении кода и спецификации правится то, что устарело, и обе части приводятся в согласие.

## Цель

- Пользователь общается с одной сессией — менеджером. Остальные роли работают в своих окнах tmux, живут независимо от менеджера; пользователь может подключиться к tmux и увидеть всех.
- Инструмент не знает о проекте. Роли, общие правила и шаблоны лежат в `<проект>/agents/` (формат — `docs/SPEC.md`, заготовка — `src/agent_team/scaffold/`, готовые роли — `examples/`). В коде инструмента нет названий конкретных проектов и трекеров и конкретных команд тестов.
- Подход взят у Gas Town: идентичность роли отдельно от сессии, состояние вне агента (трекер и git), менеджер назначает задачи, слияние и надзор — отдельные функции. Стек Gas Town (Beads, Dolt, Deacon/Dogs) не берётся.

## Что строим

CLI `team`: `init`, `check`, `up`, `spawn <роль>`, `status`, `addr <роль>`, `peek <роль>`, `attach [роль]`, `handoff <роль>`, `restart <роль>`, `send <роль> --paste`, `down [роль]`; полный список — таблица «Команды» в `docs/SPEC.md`. Раскладка: одна tmux-сессия `team-<project>`; роли — панелями одного окна (`layout: panes`, менеджер слева) или окном на роль (`layout: windows`, менеджер — первое окно). Запуск роли: worktree → сборка инструкции (тело роли + includes) → окно tmux → `claude` с `--append-system-prompt-file`, `--session-id`, ограниченным списком `--allowedTools`.

## Правила разработки

- Python 3.10+, зависимости — только PyYAML (формат ролей) и стандартная библиотека; tmux и `claude` вызываются подпроцессами.
- Права ролей — всегда ограниченный список инструментов (`--allowedTools`); `--dangerously-skip-permissions` не использовать и не предлагать.
- Инструмент не хранит и не раздаёт задачи, не сливает ветки, не ходит в сеть.
- Состояние истины — tmux; `.team/state.json` в репозитории проекта — кеш, `status` сверяет с действительностью. `.team/` не коммитится.
- Тесты: `uv run pytest`. Всё, что вызывает `claude`, подменяется переменной `TEAM_CLAUDE_BIN` (в тестах — `cat`), реальные модели в тестах не вызываются.
- Коммиты по-русски: суть изменения и причина; без строк об авторстве.
- Документы, которые агенты генерируют (отчёты, разборы), складываются вне репозитория.

## Порядок работы

Новая команда или изменение поведения проходит четыре шага:

1. Риск, который зависит от поведения живого `claude` или tmux («Открытые вопросы» в `docs/SPEC.md`), сначала проверяется на одной роли; результат записывается в спецификацию.
2. Код меняется вместе с тестом.
3. Пробный запуск на реальном проекте — без выкладки и без записи в боевые данные.
4. README, спецификация и скилл `/a-team` приводятся к сделанному.

## Что не делать

- Не вшивать в код правила конкретного проекта.
- Не ставить инструмент глобально (`uv tool install`) без запроса: запуск из репозитория через `uv run team`.
- Не запускать агентов на боевых проектах без просьбы пользователя.
