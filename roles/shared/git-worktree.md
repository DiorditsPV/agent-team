# Git и worktree

Каждая роль, которая правит файлы, работает в своём worktree на своей ветке. Так правки ролей не смешиваются, а сессию роли можно закрыть и поднять заново: работа лежит в ветке, а не в контексте агента.

- Работай только в своём worktree. В основном каталоге репозитория ничего не правь, не коммить и не откатывай: там лежат правки других сессий.
- Правь только файлы своей зоны. Общее место (схему базы, точку входа приложения) правит одна роль за раз — та, которой его поручил менеджер.
- Реализаторы в одной ветке не работают параллельно. Проверяющие и исследования только на чтение — можно.
- Коммит: сообщение называет суть изменения и причину, а также ключ задачи в трекере, если он есть. Строк об авторстве не добавляй, `--amend` не используй.
- Файлы в коммит добавляй поимённо, чтобы в него не попали чужие и временные файлы:
  - верно: `git add src/parser.py tests/test_parser.py`;
  - неверно: `git add -A`.
- Слияние в основную ветку делает только менеджер: fast-forward из ветки роли, затем полный прогон тестов. Если у проекта есть тестовая линия, ветка сначала уходит в неё.
- Push и запросы на слияние делает менеджер, если в выдаче задачи не сказано иное.
- Чужие worktree не удаляй и по маске не чисти.
