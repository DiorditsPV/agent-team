# Экономное чтение

Всё, что ты прочитал, остаётся в контексте до перезапуска роли и заново обрабатывается на каждом ходе. Лишние сотни строк дорожают с каждым следующим шагом и вытесняют то, что нужно для работы. Поэтому читай то, что нужно для текущего шага, и не больше.

## Файлы

- Сначала найди место, потом читай окно. Место ищи поиском (Grep или `grep -n`), окно читай через Read с `offset` и `limit` или через `sed -n A,Bp`. За один раз бери не больше ~150 строк.
- Файл целиком читай, только если правишь его во многих местах или ревьюишь целиком. У длинного файла (больше ~300 строк) сначала посмотри `wc -l` и решай, нужен ли он весь.
- Код читай через Read, а не через `cat`: Read показывает номера строк и режет чтение окном.

Верно:

```
grep -n "def build_instruction" src/pkg/roles.py
# → 212:def build_instruction(...)
Read(file_path=".../roles.py", offset=205, limit=60)
```

Неверно: `cat src/pkg/roles.py` или Read без `offset` и `limit` по файлу, о размере которого ты не знаешь.

## Команды

- Одно чтение на вызов. Склейка `cat a; sed -n 1,200p b; sed -n 1,200p c` тянет в контекст всё сразу, даже когда нужна только одна часть.
- Вывод, который система сохранила в файл (сообщение «Output too large», путь вида `tool-results/…`), целиком не читай. Найди нужное через `grep -n` по этому файлу и прочитай окно вокруг найденного. Или повтори команду с фильтром.

Верно: `grep -n "FAILED" <путь из сообщения>`, затем окно в 40 строк вокруг нужной.

Неверно: Read сохранённого файла целиком, чтобы «посмотреть, что там».

## Git

Сначала сводка, потом дифф нужного файла:

```
git diff --stat
git diff -- path/to/file.py
git show --stat <коммит>
git log --oneline -n 20
```

Неверно: `git diff` или `git show <коммит>` без `--stat` в ветке, где изменено много файлов, и `git log` без `-n`.

## Сборка и тесты

Вывод пиши во временный файл. Читай код завершения самой команды и хвост вывода; полный вывод открывай, только когда команда упала.

```
out=$(mktemp); <команда> >"$out" 2>&1; echo "exit=$?"; tail -n 40 "$out"
```

При падении ищи причину по файлу:

```
grep -nE "error|FAIL|failed" "$out" | head -n 60
```

Неверно: `<команда> | tail -n 40` без кода завершения (код `tail` подменяет код команды) и запуск без фильтра, когда вывод длинный.

## Обзор чужого кода

Код, который ты не правишь и не ревьюишь, а хочешь понять (где что лежит, как части связаны), обзори через субагента Explore. Проси короткий ответ: пути, строки, связи. Так в твой контекст попадёт вывод, а не прочитанные им файлы.
