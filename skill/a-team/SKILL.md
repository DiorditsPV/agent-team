# a-team

Ведёт пользователя через работу с командой агентов проекта: подключение, подъём в tmux, передачу дел менеджеру и остановку. Исполнитель всех действий — CLI `team` из репозитория agent-team.

**Каталог инструмента** — клон репозитория agent-team, в котором лежит этот скилл (`<клон>/skill/a-team/`; в `~/.claude/skills/` скилл подключён симлинком). В клоне лежат формат ролей (`docs/SPEC.md`, раздел «Роль»), готовые роли (`examples/roles/`, каталог — `examples/README.md`) и описание команд (`README.md`).

## Аргумент

`/a-team [init | up | status | handoff <роль> | down [роль]]`. Без аргумента сценарий выбирается по состоянию (шаг 1).

## Процесс

### 1. Состояние

- Найти каталог инструмента: перейти в базовый каталог этого скилла (Claude Code называет его при загрузке скилла строкой «Base directory for this skill»; если такой строки нет — `~/.claude/skills/a-team`) и подняться на два уровня по настоящему пути, а не по симлинку:

  ```bash
  cd "<базовый каталог скилла>" && cd "$(pwd -P)/../.." && pwd
  ```

  Готово, когда в найденном каталоге есть `pyproject.toml` с `name = "agent-team"`. Дальше этот путь называется `<клон>`.
- Проверить, что `tmux` и `claude` есть в `PATH`. Без них не продолжать: сказать пользователю, чего не хватает.
- Проверить, что `team` есть в `PATH`. Если нет и есть `uv`, во всех шагах ниже вместо `team` вызывать `uv run --project <клон> team` из каталога проекта. Если нет и `uv`, не продолжать: сказать пользователю, что нужен `uv`.
- Сам инструмент глобально не устанавливать: это решение пользователя. Если `team` нет в `PATH`, в выходе назвать команду установки `uv tool install --editable <клон>`.
- Корень проекта: `git rev-parse --show-toplevel`.
- `agents/team.yaml` есть → `team check` и `team status`.
- Выбор сценария без аргумента:
  - `agents/` нет → «Подключить проект»;
  - tmux-сессии нет → «Поднять команду»;
  - сессия есть → «Состояние».

Готово, когда сценарий выбран и сказан пользователю одной строкой.

### 2. Подключить проект (init)

1. `team init` в корне проекта. Готово, когда `agents/team.yaml` создан, а `team` перечислил созданные файлы.
2. Изучить проект: `CLAUDE.md`, `README`, структуру каталогов, команду тестов, трекер задач (есть ли строка подключения трекера в `CLAUDE.md`). Правила безопасности и запреты брать только из документов проекта, не придумывать.
3. Предложить пользователю состав: менеджер и один–три исполнителя. Подходящие роли брать из `<клон>/examples/roles/`: когда какая нужна — в `<клон>/examples/README.md`. У каждого исполнителя своя зона файлов, зоны не пересекаются, общие файлы (точка входа CLI, миграции) отданы одной роли. Показать таблицей «роль — за что отвечает — зона — модель» и получить согласие одним вопросом. Без согласия файлы ролей не писать.
4. Записать роли по формату из `<клон>/docs/SPEC.md`, раздел «Роль». Роль из библиотеки копировать вместе с файлами её `includes` в `agents/shared/` и заменять заполнители `<…>`. Правила:
   - значение `description` всегда в кавычках, потому что `: ` внутри ломает разбор;
   - у роли, которая правит код, свой `worktree {dir, branch}`;
   - модель менеджера — `opus`, исполнителей — `sonnet`, если пользователь не сказал иначе;
   - `allow` — только то, что нужно сверх набора по умолчанию: MCP трекера, `Bash(gh *)` менеджеру. `--dangerously-skip-permissions` и `bypassPermissions` не предлагать;
   - правило, общее для нескольких ролей, — один файл в `agents/shared/`, роли подключают его через `includes`.
5. Заполнить `team.yaml`: `test_command`, `worktree_root`, `layout` (по умолчанию `panes`), `start` у ролей. Менеджер — `manual`, исполнители — `on_demand`.
6. `team check`. Готово, когда ошибок 0. Предупреждения показать пользователю.
7. Спросить, коммитить ли `agents/`. Без слова пользователя не коммитить. Добавить `.team/` в `.gitignore` проекта.

Затем перейти к шагу 3, если пользователь хочет поднять команду сейчас.

### 3. Поднять команду (up)

1. `team check` — ошибок 0.
2. `team up`, через 10 секунд `team peek manager 30`.
   - Видно «Do you trust this folder» / «Quick safety check» → не отвечать за человека. Сказать пользователю: `team attach`, выбрать «Yes, I trust this folder», `Ctrl-b d`.
   - Готово, когда в выводе панели есть строка модели и пустое поле ввода, а `team status` показывает менеджера «работает».
3. Передать дела менеджеру. Это первое сообщение ему, поэтому без него он начинает с чистого контекста. Собрать из этого разговора и трекера:
   - задачи в работе и их статус;
   - ветки и worktree с незаконченной работой;
   - принятые решения, которых нет в файлах;
   - что ждёт решения пользователя.

   Отправить через `SendMessage` на адрес из `team addr manager` (вида `uds:…`), а не по имени: имена сессий бывают неуникальны. Если адреса нет или доставка не прошла — сказать пользователю; `team send manager --paste` только с его согласия, потому что вставка выглядит как ввод пользователя. Готово, когда в `team peek manager` видно, что сообщение принято в работу.
4. С этого момента текущая сессия ролями не управляет: задачи раздаёт только менеджер в tmux, иначе у команды два источника указаний.
5. Сказать пользователю, как подключиться:
   - `team attach`;
   - говорить только с менеджером;
   - стрелка с префиксом `Ctrl-b` — соседняя панель, `Ctrl-b z` — развернуть панель, `Ctrl-b d` — отключиться, не останавливая агентов.

### 4. Состояние (status)

`team status` и `team peek` по каждой работающей роли (20 строк). Кратко пересказать:
- кто жив;
- кто ждёт ответа человека: вопрос о доверии к папке, запрос права;
- кто молчит дольше часа.

Ничего не отправлять ролям.

### 5. Передача и перезапуск роли (handoff)

1. `team handoff <роль>`.
2. Через минуту `team peek <роль> 60`. Готово, когда передача по шаблону видна в выводе.
3. Если пользователь просил перезапуск — `team restart <роль>` (та же сессия) или `--fresh` (новая, контекст из передачи).

### 6. Остановка (down)

- Для каждой роли с незаконченной работой (по `peek`: правки без коммита, задача в процессе) — сначала шаг 5.
- Затем `team down <роль>` или `team down` для всей команды.
- Готово, когда `team status` показывает «не запущена».

## Общие правила

- Сообщения ролям — только `SendMessage` на адрес из `team addr <роль>`. `team send --paste` — запасной путь: перед ним `team peek`, и если в поле ввода уже есть текст, не вставлять.
- Не нажимать за человека ответы на вопросы о доверии и правах.
- Роли закрывает только менеджер или пользователь. Скилл закрывает их только по команде `down`.

## Выход

Пользователю одним сообщением:
- что сделано: сценарий, команды, итог `team check` и `team status`;
- как подключиться;
- что ждёт его ответа.

Проверка скилла — `scenarios.md` рядом; читать, когда скилл меняется.
