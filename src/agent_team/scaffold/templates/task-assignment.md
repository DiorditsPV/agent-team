# Выдача задачи исполнителю

Менеджер пишет исполнителю сообщением в этом виде. Поля обязательны, пустое поле — «нет».

```
Менеджер: <ID задачи> — <заголовок>
Название: <8–48 знаков, для владельца: что станет иначе для него, без номера и имён из кода>
Зона: <роль / зона файлов>
Задача: <что сделать, одним абзацем>
Результат: <что должно быть в конце: ветка, тесты, числа>
Файлы: <список файлов, которые можно править; остальное — только читать>
Ветка/worktree: <имя>, от <откуда>
Ограничения: <без выкладки, без записи в боевую базу, чужие зоны, сроки окон>
Зависимости: <от каких задач и веток, что уже слито>
Остановка: <условия, когда отчитаться и ждать>
Проверка: <полный тест / судья нужен или нет>
```

То же название менеджер ставит агенту командой `team task <агент> "<название>" --id <ID задачи>`: владелец видит его в `team status`.

Режим «до пустой очереди» добавляется строкой: `Режим: до пустой очереди зоны; остановка — очередь пуста, нужно решение менеджера, упёрся в чужую зону или ожидание, падают тесты без найденной причины`.
